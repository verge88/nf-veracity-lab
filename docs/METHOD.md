# Методика эксперимента

## Связь с исходным обсуждением

Сохраняется постановка: самоотчёт NF — недоверенное утверждение, которое сопоставляется с независимым SBI-наблюдением; КИЕ обеспечивает дополнительное измерение свежести и доступности; однотипные NF задают пространственный контекст. Проверяется прирост M3→M4. Сам факт сбора нескольких источников данных или challenge-response не заявляется научной новизной.

Доступная выгрузка исходного чата содержит сокращённые главы. Поэтому приведённые ниже нормировки, веса, окно и алгоритм обучения являются явной операционализацией для этого проекта, а не дословно восстановленными окончательными формулами диссертации. Полные вложения диссертации в этот проект не поступали.

## Наблюдения и признаки

Для окна t и экземпляра i:

- O_i = (число обычных запросов / длительность окна, доля ответов >=400, доля операции read).
- R_i — те же величины из самоотчёта; КИЕ и сами отчёты исключаются из обычного потока.
- L_i — средняя задержка независимого наблюдателя; она включает транспорт, SCP и обработку.
- A_i — измеренная проверяющим задержка КИЕ и признак ошибки/таймаута/неверного nonce, digest или NF ID.

Все три координаты R и O относятся к одной NF, направлению и закрытому окну. Live-режим использует завершение всех запланированных запросов до получения отчёта; при переполнении окна прогон считается незавершённым. Это барьерная экспериментальная синхронизация, не решение произвольного clock skew в распределённой сети.

Для каждой сопоставимой группы g по нормальным **обучающим** прогонам:

    s_g,k = max(1.4826 * median(|O_k - median(O_k)|), epsilon_k)
    epsilon = (0.5 запроса/с, 0.01, 0.02)
    D_rep(i,t) = mean_k |R_i,k(t) - O_i,k(t)| / s_g,k
    D_peer(i,t) = mean_k |O_i,k(t) - median_{j != i, j in g} O_j,k(t)| / s_g,k

MAD оценивается по истории нормальных тренировочных наблюдений всей сопоставимой группы; фиксируется до тестирования и не пересчитывается на тестовых атаках. Это защищает нормировку от загрязнения текущим нарушителем. При отсутствии отчёта D_rep=0, а report_missing=1 — отдельный признак, а не выдуманное измерение рассогласования. Минимум — две другие NF. Разные типы NF и разные классы нагрузки нельзя объединять в одну группу.

Временные признаки: |rate_t-rate_(t-1)|, |mix_t-mix_(t-1)|, отклонения от EWMA предыдущих окон (alpha=0.3). История сбрасывается между прогонами. Данные будущих окон не используются. D_peer использует текущее завершённое окно, поэтому решение выдаётся в его конце.

| Модель | Признаки |
|---|---|
| M0 | интенсивность, доля ошибок, доля read, задержка SBI |
| M1 | M0 + временные признаки |
| M2 | M1 + КИЕ |
| M3 | M2 + D_peer |
| M4 | M3 + D_rep + отсутствие отчёта |

Дополнительно: M4 без КИЕ, без D_peer, без временных признаков, D_rep-only. Основное сравнение M3→M4 добавляет блок отчётности. В поставляемых сценариях отчёты не пропадают, поэтому прирост не обусловлен report_missing; при экспериментах с потерями необходимо дополнительно разделить этот блок.

## Шесть сценариев

| Сценарий | Изменение | Метка attack | Метка falsification |
|---|---|---:|---:|
| normal | обычная нагрузка, честный отчёт | 0 | 0 |
| load-spike | общий легитимный всплеск, честный отчёт | 0 | 0 |
| DoS | ограниченный поток + искусственное насыщение очереди/ошибки одной NF | 1 | 0 |
| compromised-NF | доля read меняется при допустимом объёме, честный отчёт | 1 | 0 |
| falsified-report | обычный поток, заниженные счётчики/изменённая доля read | 1 | 1 |
| low-and-slow | постепенный дрейф поведения с сокрытием его в отчёте | 1 | 1 |

В live DoS означает управляемую имитацию отказа/перегрузки экспериментальной NF, а не попытку обрушить NRF/SCP. Максимум 20 запросов/с на NF, в конфиге обычная нагрузка 2 запроса/с. Значение low-and-slow задаётся линейным нарастанием доли read и сокрытием в отчёте; синтетический вариант дополнительно изменяет интенсивность.

Метки задаёт оркестратор вмешательства и сохраняет отдельно от признаков. Это известная истина экспериментального сценария, не автоматическое доказательство компрометации. D_rep также реагирует на дефекты учёта, потери и временную рассинхронизацию: сам по себе он не доказывает умысел.

## Обучение и оценка

Используется один и тот же RandomForest (100 деревьев, max_depth=10, min_samples_leaf=5, balanced_subsample) для всех наборов признаков. Разбиение 60/20/остаток по целым прогонам отдельно для каждого сценария; минимум 5 прогонов на сценарий. Порог выбирается по F1 только на validation, затем фиксируется. Варианты M0–M4 не используют run_id, scenario, номера окон, метки, имена NF или режим как входы.

Это **обучение с размеченными атаками известных сценариев**, а не доказательство обнаружения неизвестных атак. Для проверки обобщения нужен отдельный leave-one-scenario-out протокол и реальные записи другой нагрузки. Здесь они не подменяются случайным перемешиванием окон.

Экспортируются Precision, Recall, F1, FPR, ROC AUC, average precision, confusion matrix по сценарию и суммарно. AUC при одном классе — null/пустое поле. Время обнаружения считается от первого вредоносного окна до конца первого положительного окна (минимум одна длительность окна); пропущенные эпизоды учитываются отдельно и не получают нулевую задержку. Доверительный интервал разницы F1 — парный bootstrap целых тестовых прогонов.

Накладной трафик КИЕ — отношение учитываемых байтов прикладного сообщения к обычному трафику; не wire-level bandwidth. В симуляторе размеры условные, в live размеры сообщений измеряются. NRF heartbeat и отчёты не включены. Для полного сетевого overhead используйте PCAP и отдельный базовый прогон без КИЕ. Измеренные training/prediction timings относятся к текущему компьютеру и не характеризуют производительность Open5GS.

## Границы модели доверия

Наблюдатель, оркестратор и большинство сопоставимых NF считаются доверенными. В данном стенде они разделены логически; Python-процессы одного live-прогона не являются аппаратно изолированными trust domains. Компрометация наблюдателя или прямой обход SCP нарушают предпосылки. Для настоящей NF нужны сетевые политики, запрещающие прямой обмен, отдельный хост/namespace наблюдателя и контроль полноты захвата.

КИЕ содержит случайный nonce и SHA-256 тела запроса; проверяющий сверяет ответ и самостоятельно измеряет время. Хеш не является подписью или удалённой аттестацией. Скомпрометированная NF может правильно отвечать на КИЕ. Код намеренно не делает противоположного предположения. Распознавание и выборочное обслуживание контрольного трафика — дополнительный эксперимент, а не закрытая этим стендом проблема.

Синтетические результаты подтверждают работоспособность обработки и заложенные различия генератора. Они не подтверждают научную новизну и не являются эмпирическими результатами на Open5GS.
